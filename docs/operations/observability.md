# Local operator telemetry

API requests create OpenTelemetry server spans named by route template. Incoming W3C `traceparent` headers continue the caller's trace. Status, route and latency are measured even when an exception escapes. Structured request logs and Prometheus OpenMetrics histogram/counter exemplars share the active trace ID. Raw query strings, request bodies, provider error strings and exception stack events are excluded from request telemetry. The logging processor redacts sensitive dictionary fields, credential-bearing URL query parameters and URL user information before JSON rendering and OTLP export. Client URL INFO logging is disabled. Uvicorn access log arguments pass through a credential redaction filter. Unexpected request exceptions produce a sanitized HTTP 500 response, preventing the server from printing a raw exception traceback. An actual Uvicorn subprocess test verifies both exception-secret and request-query-secret exclusion.

The `telemetry` service is the standard Grafana OTEL LGTM development image: OpenTelemetry collector, Tempo, Loki, Prometheus and Grafana. API export uses OTLP HTTP at `http://telemetry:4318`; bounded background export queues and two second timeouts isolate application responses from backend failures. The dedicated project Prometheus also scrapes API, normalizer, archive and the semantic journey probe. Enable its exemplar storage flag. `infra/observability/datasources.yml` provisions Traffic-Prometheus with exemplar links to Tempo. Grafana Explore can inspect a trace and search Loki structured bodies for its `trace_id`. The optional collector configuration is for a separate forwarding collector; do not mount it over the LGTM image's built-in configuration.

Persist the LGTM image's `/data` directory (including Tempo/Loki/Grafana stores), the external Prometheus data directory and the oncall state directory. A Compose restart retention check must verify the specific image's data paths; configuration alone does not prove retention. `dashboards/operator.json` is an importable overview dashboard. This local backend is a development demonstration, not hosted production monitoring.

Validation covers JSON credential redaction, correlated request span/log/exemplar, exception metrics, semantic journey empty-data behavior, authenticated receiver, signed restricted executor, duplicate delivery and persisted resolution. `tests/observability/alerts.test.yml` checks sustained firing and recovery with promtool. Runtime acceptance additionally requires an actual stored trace/log lookup, a backend restart retention check and an isolated fault-to-resolved run; record these only after execution.
